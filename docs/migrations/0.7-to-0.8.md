# 0.7 → 0.8 迁移说明

> 本文记录 0.7 到 0.8 的历史迁移。安装当前版本请参考 [安装和升级指南](../packaging-and-installation.md)。

## 安装

```bash
# npm
npx -y cybertron-agents@0.8.0 init --apply
# pipx
pipx upgrade cybertron-agents
cybertron init --apply
```

安装后重新运行 `models setup`，并重启 OpenCode。全局安装的 13 个角色 Markdown、`opencode.jsonc` 和 `shell_policy.mjs` 会更新。

## 配置变化

- `prima` 新增 `cy_escalate` 权限；
- `liege-maximo` / `micronus-prime` 改为“项目根只读 + 凭据 deny-list”；
- `vector-prime` 新增 `git add/commit/tag/push` 的 `ask`，成为 Git 写 owner；
- 旧的项目级 `.opencode` 与全局安装仍不能同时存在；先移除一处，或使用 `--allow-duplicate`（不推荐）。

## 运行数据

- 0.7.x 的 v6 run 仍可读；`cybertron v6 runs/show/grants/lineage` 可直接查看；
- v5 `cybertron run/session/workflow` 仍可用但会打印 legacy 警告；新任务使用 `cybertron v6` 或 OpenCode 内的 `cy_plan`；
- 旧 v5 `SessionStore` 的 UUID 目录不迁移，继续按 UUID 寻址。

## 行为变化

- 新 run 的 Intent 必须 `confirmed=true`；
- 节点 `requires` 缺失时，`before()` 返回 `needs_grant`，不会派发；
- `test` 证据必须绑定到覆盖节点；旧的 run-level gate 不再满足 intent 的 `test` 条件；
- `danger-full-access` 的常规跨区域读写自动放行，但高危动作仍需 `dangerous.confirm`；
- 飞书 `external.write` 可用 `standing` Grant（8h 滑动 / 24h 上限）。

## DSH

DSH 仍是实验性第二宿主：

- `cy_escalate` 只创建请求，宿主需外部批准；
- 没有 13 角色子会话 write_scope 绑定；
- full-access 拦截器与审查者读守卫只在 OpenCode 插件中生效。

完整 13 角色治理以 OpenCode 为准。
