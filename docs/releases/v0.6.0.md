# Cybertron Agents 0.6.0

发布日期：2026-11-18

0.6.0 把 Cybertron 的默认安装模式改为**全局安装**：13 个角色、`/cybertron` 命令、插件和 Python 运行时只放在 `~/.config/opencode`。项目目录只保留运行产物、模型覆盖和源码，不再默认生成项目级 `.opencode`。

## 默认安装模式变化

```bash
cybertron init --apply            # 默认：全局安装
cybertron init --apply --project . # 显式：项目级安装
```

- **全局安装**：`~/.config/opencode/{agents,commands,plugins,cybertron-runtime}`，所有项目共用。
- **项目落盘**：每个项目自己的 `.cybertron/runs/<slug>/`（`plan.json`、`events.jsonl`、`run.json`）和 `<project>/.cybertron/models.json` 模型覆盖；源码仍按节点 `write_scope` 写入项目。
- **默认不再生成项目级 `.opencode`**，避免全局和项目两份插件/agent 重复加载。

## 重复安装拦截

- `cybertron init` 检测到另一处安装时直接拒绝，并提示先移除其中一处；高级场景可用 `--allow-duplicate` 显式放行。
- `cybertron doctor` 报告“另一处安装”，并提示只保留一处。
- Python、npm、Shell 三个安装入口行为一致。

## 项目级能力不受影响

全局安装只决定 agent/插件/运行时在哪；会话工作目录仍是项目根：

```text
<project>/.cybertron/runs/<slug>/{plan.json,events.jsonl,run.json}
<project>/src/**（按 write_scope）
<project>/.cybertron/models.json（可选，优先于全局模型）
```

## 修复

- 包含 0.5.1 的 `shell_policy.mjs` 安装修复。
- `doctor` 同时检查 `cybertron.js`、`hook_logic.mjs`、`shell_policy.mjs` 与 Python 运行时。

## 安装 / 升级

```bash
# 全局（推荐）
cybertron init --apply
cybertron doctor --global

# 可选：项目级模型覆盖
cd /path/to/project
cybertron models setup --project .

# 如果项目里还留着旧的 .opencode
# 先移到备份目录或删除，再重新打开 OpenCode
```

npx：

```bash
npx -y cybertron-agents@0.6.0 init --apply
```
