# Cybertron Agents 0.7.1

发布日期：2026-11-18

0.7.1 增加**项目外写入的受控通道**：计划节点可以声明 `external_scope`，把项目外路径纳入计划；升权方式跟随宿主——OpenCode 用它原生的 `ask` / `once` / `always` 权限卡，DSH 用会话模式与单次 `sandbox_permissions`。Cybertron 不再维护第三套审批机制。

## 变化

- `PlanNode` 增加 `external_scope`：只接受字面路径（绝对路径或 `~`），拒绝 glob、`..` 和 `.git` / `.opencode` / `.cybertron/runs` / `opencode.jsonc`；`read-only` 与 `danger-full-access` 下不可用。
- OpenCode 子会话规则：项目 `write_scope` 直接 `allow`，声明过的外部路径 `ask`，其余外部路径 `deny`。
- `permission.evaluate` 钩子只做两件事：把未声明的外部路径强制 `deny`，并把判定记入账本（`permission.requested` / `permission.granted`）。它不会把用户的 `allow` 改回 `ask`，所以「总是允许」可以生效。
- 插件订阅 `permission.replied`，把 `once` / `always` / `reject` 记成 `permission.resolved`；收到 `always` 时额外记录一条 run 级授权，后续同一 scope 不再弹卡。
- `finish` 对 `external_scope` 产物做 SHA-256；OpenCode 下还要求同一 `call_id` 的批准记录，缺失则节点 `failed`。DSH 下只记哈希，审批留在宿主侧。
- `run.json` 与 `cy_state` 增加 `host` 和 `evidence_level`：OpenCode 为 `kernel-receipt`，DSH 为 `host-approved`。
- DSH bundle 文档明确：升权沿用 DSH 的会话模式与单次升权，bundle 不签发自己的审批。

## 已知限制

- DSH 仍未接入 dispatch 绑定；当前只提供计划与账本访问。
- `permission.replied` 的订阅依赖插件运行时把事件流暴露为异步可迭代对象；拿不到时只记请求、不记答复，主流程不受影响。
- 项目外写入没有快照与回滚，只有产物哈希。
- OpenCode 的「总是允许」会保存项目级 allow 规则；若工具没有提供保存 pattern，则依赖 Cybertron 自己的 run 级授权。

## 升级

```bash
# 全局安装
cybertron init --apply
cybertron doctor --global

# 或 npm
npx -y cybertron-agents@0.7.1 init --apply
```

升级后重启 OpenCode。项目目录不需要 `.opencode`；run 账本仍在 `<project>/.cybertron/runs/`。

## 验证

```bash
python3 -m unittest discover -s tests
python3 -m cybertron.stage5_verify
python3 cybertron_primes_engine.py
node --test tests/v6_plugin_runtime.test.mjs tests/v6_plugin_hook.test.mjs tests/dsh_adapter_bridge.test.mjs
python3 scripts/bump_version.py --check
```

本机在受沙箱限制的环境里，5 项依赖嵌套 `sandbox-exec` 的用例会报 `Operation not permitted`；这些用例在 CI 的 macOS runner 上运行。

## 升级注意

- 已有 run 的 `run.json` 没有 `host` 字段时按 `opencode` 处理。
- `external_scope` 与 `danger-full-access` 互斥；外部路径在 `danger-full-access` 下继续写在 `write_scope` 里。
