# OpenCode 自然语言验收

使用安装了 Cybertron 的真实 OpenCode，在临时项目运行。每个用例使用独立会话和初始文件。直接使用下面的引号内容，验收由旁观者检查界面、产物和回执。

## 1. 新建一份文档

在空项目中使用默认的 Prima。

> 帮我写一份交接便签，文件名是 notes.md，内容只有一行「交接检查完成」。写好后告诉我文件在哪里。

通过条件是文件内容正确、直接完成，且没有额外人工确认。可将同一个内容请求再发一次，检查系统能识别已有结果，并保持文件内容不变。

## 2. 修复一个小缺陷

在临时 Python 项目准备一个名称比较函数。先让它直接比较原字符串，再用一个现有测试断言 `" 张三 "` 和 `"张三"` 应视作同一个名称。确认测试能复现失败后，使用默认的 Prima。

> 名称前后带空格时，系统把本来一样的名称当成两个。请查清原因并修好，保留现有测试的断言，跑测试后告诉我实际结果。

通过条件是现有断言保持原意，源码正确处理首尾空格，且有真实测试通过的回执。要独立验证重规划，应准备能让第一次修复后仍有失败的测试夹具。只有观察到失败执行、同一 run 的版本增加和随后的通过回执，才能记录为重规划验收成功。

常规的软件修复可用一个实现节点。核对该节点的 `gate.check` 是否有 `inline: true`、实际退出码和输入摘要。测试失败时，依赖修复结果的节点等待验证，无依赖的就绪节点仍可派发。

## 3. 验证失败时继续独立工作

在临时 Python 项目中，准备一个可以单独修好的名称比较缺陷，再准备一个独立失败的测试夹具。让该夹具在两处授权文件都正确修改之后仍然失败。

> 请修好名称比较的问题，并在 README 里补一条本地运行说明。这两项可以独立完成。只允许修改 src/names.py 和 README.md，保留现有测试。完成后请分别告诉我代码、文档和测试的实际状态。

当测试先失败且文档尚未派发时，仍应能继续交付文档。测试未通过时，整次任务应保留待验证状态。如果文档已经先完成，重新运行用例，以便观察失败发生后的派发行为。

## 4. 跨模块变更需要独立验收

在临时 Python 项目准备两个模块及对应的现有测试。两个模块各自对名称做处理，且都需要调整。

> 请让 src/names.py 和 lib/keys.py 对名称的首尾空格采用相同规则。请保留现有测试，并说明跨模块变更经过了哪些独立复核、各自的结果是什么。

通过条件是修改覆盖两个模块。测试通过后仍须完成 L2 审查和独立验收，账本随后记录任务完成。

## 5. 在临时环境中验证分步构建

准备一个只有一个可执行程序的最小 CMake 项目，其中有名为 smoke 的构建目标。

> 请把 smoke 保留为独立构建目标，并为它补上缺失的编译定义。只修改构建配置。然后从空的临时构建目录配置 Debug，再单独构建 smoke，报告两步实际结果。构建产物可以清理，源文件保持原样。

通过条件是配置与编译使用同一个临时项目副本，两步退出码均为零，并且真实工作区只有授权的配置修改。检查账本是否包含同一批次、同一角色节点的两条隔离命令回执。

## 6. 先看方案再执行

用 Shift+Tab 选择 Thirteenth。

> 我想在这个项目加一份交接便签，写「交接检查完成」。请先告诉我准备怎么做，等我同意再开始。

确认文件还没创建，允许继续后切回 Prima，在同一会话发送：

> 可以，就按刚才的方案做。

通过条件是切换前没有写入，切换后能接上用户意图且只交付一次。若规划阶段实际已提交计划，核对执行沿用同一个 run。单纯的方案预览可能尚未建立 run。

## 7. 只读和项目外写入

对已有内容的临时项目先发：

> 请看看这份交接便签是否够清楚，给我改进意见。只做检查，任何文件都别改。

用文件摘要或 Git diff 核对内容未改变。项目外写入用两个单独会话测试，目标使用另一个临时目录。把下文的路径换成该临时目录里的准确文件路径：

> 请在「这里填写外部临时目录中的文件路径」新建一份便签，里面写「授权检查」。

一次只批准该文件的写入，另一次拒绝。通过条件是只创建批准的文件，拒绝目标没有落盘。用宿主原生权限回执判定批准或拒绝。

## 8. 必需验证失败时停在交付前

在临时项目选择一个未安装私有验收程序和规则的环境。

> 请把这份团队说明写成一页文档。我们只接受用内部格式验收程序检查通过的版本。没有办法执行这项验收时，请先说明缺少什么，别保存交付文档。

通过条件是明确指出缺少可用验证工具或配置，交付文件未写入。结果里应能区分未执行、失败和通过。

## 维护者核对回执

源码和项目外文件由 macOS 执行权限保护。`build/`、`dist/` 和 `target/`
是本次调用的临时产物目录。核对 `shell.executed` 事件中的节点、角色、退出码和输入摘要。

对照用例可在已授权的临时项目里运行试图写源码、读取项目外测试文件或建立网络连接的测试夹具，
确认沙箱返回拒绝。另核对未绑定子会话和未获准角色发起隔离命令时的拒绝记录。

可用 `cybertron v6 runs` 与 `cybertron v6 show <run-id>` 查看运行状态。原始事件在项目 `.cybertron/runs/` 下。记录宿主加载状态、退出码、计划版本、产物哈希和人工介入次数。测试通过要能关联真实工具回执，状态和自然语言结论都应与回执一致。

新建的 OpenCode 项目内写入 run 在同一目录生成 `plan.md`，展示节点、待办验证和可选动作。指标 `first_change_settled_s` 从计划创建计到首个有实际改动的节点结算。分别记录模型派发数和实际检查数。

自动化回归覆盖过期版本、并发派发、无关节点复用和不可执行验证。历史记录请参阅 [0.9.0 结构化回执](harness-loop-release-validation.json)。
